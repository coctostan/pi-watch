## Overview

v0.3 made pasted YouTube URLs a first-class input for pi-watch. Supported URLs resolve into sampler-owned local media, human or automatic captions feed the cheapest transcript tier when available, visual tiers remain the fallback, and the complete tool/command path is covered by deterministic tests plus a bounded opt-in live smoke. Git and local Pi installations ship loadable compiled output with setup and troubleshooting documentation.

## Milestone Constraints

- YouTube-first support remains behind a generic resolver seam.
- `yt-dlp` is an external runtime prerequisite, not an npm dependency.
- Captions are preferred; Whisper/local ASR remains deferred.
- No cloud service or provider key is mandatory.
- Caption absence degrades to existing visual tiers without fabricated spoken content.
- Local-file behavior and tier-2/tier-3 contracts remain stable.
- Caller-controlled refs use argv-only execution, bounded timeouts, and explicit owned cleanup.
- Default tests remain offline and deterministic; real YouTube proof is opt-in.
- Installation uses Git/local Pi sources. The unscoped `npm:pi-watch` registry package is unrelated.

## Milestone Summary

### Key Accomplishments

- Added secure YouTube URL resolution into sampler-owned local media while preserving caller refs and local-file behavior.
- Made transcript-first routing real for supported YouTube videos through bounded human/automatic caption acquisition and pure WebVTT parsing.
- Preserved deterministic visual fallback across absent captions and resolver/caption failures.
- Proved pasted URLs through the actual registered `watch` tool and `/watch` command boundaries.
- Added a bounded opt-in live YouTube smoke through the production path.
- Shipped Pi-loadable compiled output plus complete Git/local installation and troubleshooting documentation.
- Finished with 194 passing tests, 2 default-skipped live tests, and passing typecheck/build gates.

### Key Decisions

- Preserve separate `originalRef` and `mediaRef`; only resolver-created storage is sampler-owned and removable.
- Run `yt-dlp` with argv arrays, explicit bounds, and `--ignore-config` so caller input and local configuration cannot widen execution behavior.
- Prefer human captions, then make at most one automatic-caption fallback; every failure returns transcript source `none`.
- Bound caption data before timeline assembly with a 16 MiB pre-read cap and duration-aware cue filtering.
- Commit exact generated `dist/**` output instead of adding prepare/install hooks or dependencies because Pi Git installs omit dev-only build tooling.
- Use verified Git/local Pi package sources and explicitly reject the unrelated unscoped registry package.
- Keep real YouTube verification opt-in, bounded, overrideable, public-URL-only, and secret-free.

### Issues Resolved

- Supported YouTube URLs previously could not enter the local sampler pipeline.
- Transcript acquisition was a stub, so spoken-content questions could not reach tier 1 from captions.
- Cleanup errors could obscure primary sampling failures; both causes are now preserved.
- WebVTT character references, out-of-duration cues, and oversized caption files received explicit handling and regression coverage.
- Pi-equivalent Git installs lacked TypeScript build tooling; committed distributable output now keeps the extension loadable.
- The default live fixture became unavailable; the plan-authorized public override completed the required proof.

### Issues Deferred

- Tier-3 batch fan-out for frames across many videos.
- Optional Gemini/cloud tier.
- Optional resolver download filesize/duration caps if operational evidence warrants them.
- Whisper/local ASR for videos without captions.
- Scoped npm package rename/publication; Git/local sources remain the supported distribution path.
- Dependency maintenance for the unchanged dev tree, currently reported as 0 critical / 4 high / 2 moderate.

### Technical Debt

- `src/sampler/effects.ts` is a focused, test-backed future decomposition candidate after caption and source-resolution effects expanded it beyond 600 lines.
- A dedicated CI workflow beyond existing Socket Security checks remains carried forward.
