The Core Value remains “cheapest-path-that-works video understanding for the agent — local-first, model-agnostic.” The three completed milestones form a direct progression toward it: v0.1 built the sampler/router/tool/tier foundation, v0.2 proved and explained the optional local tier-2 path, and v0.3 made pasted YouTube URLs reach caption-backed tier 1 with visual fallback. ## Strategic Options

- **A. Local speech coverage — make tier 1 work for local files and captionless videos** — Add a bounded, local-first ASR seam (likely Whisper-compatible) that runs only when captions are unavailable. **Value:** very high; closes the largest remaining gap in the “cheapest path that works” promise. **Cost:** medium-high. **Risk:** model/runtime lifecycle, long-media resource bounds, temporary audio ownership, and probabilistic transcript quality. **Dependencies:** a clean effect boundary, deterministic audio fixtures, and explicit fallback policy.
- **B. Trust and regression infrastructure** — Add dedicated GitHub CI for test/typecheck/build, a durable evaluation/result format, representative deterministic media fixtures, and bounded performance/correctness baselines. **Value:** high for safe iteration and release confidence. **Cost:** medium. **Risk:** low-medium; answer-quality assertions can become brittle if they depend on live models. **Dependencies:** separate deterministic contract gates from opt-in live evidence.
- **C. Multi-video visual scale** — Implement tier-3 batch fan-out so many videos can be visually analyzed without manual single-video follow-ups. **Value:** high for research/comparison workflows, lower for ordinary single-video use. **Cost:** high. **Risk:** high; context growth, concurrency, cancellation, result ordering, and subagent orchestration are exactly why this was deferred. **Dependencies:** explicit per-item/context budgets and a proven orchestration design.
- **D. Adoption and operational polish** — Add a scoped package publication path, richer command/config UX, resolver download/duration caps, dependency maintenance, and focused source decomposition. **Value:** medium-high for installation and operations. **Cost:** variable. **Risk:** medium because this mixes unrelated concerns unless narrowed to one outcome. **Dependencies:** package-name decision and clear compatibility policy.

## Ranked Recommendation

**Recommended next target (non-authoritative): Option A — local speech coverage, with the minimum structural and validation work needed to keep it bounded.**

**Why this ranks first:** v0.3 made transcript-first routing real, but only where YouTube already supplies captions. Speech-heavy local files and captionless public videos still pay for visual inference or receive weaker evidence even though a local transcript would be cheaper and more directly relevant. The contract, router, and fallback chain already exist, so ASR extends the proven architecture instead of replacing it. It is the clearest user-visible improvement and the closest fit to the Core Value. Option B should supply guardrails within or immediately around that work, but CI alone does not close a functional gap. Options C and D are valuable after the single-video understanding path covers the common speech case.

> Non-authoritative: this recommendation informs the milestone discussion but does not decide it. Only a future approved PLAN authorizes implementation.

## Actionable Points

- [ ] Preserve captions-first behavior and make every ASR setup/runtime failure degrade to the existing tier-2/tier-3 chain without blocking or fabricated text.
- [ ] Use deterministic speech fixtures to assert transcript timing, tier-1 routing, and fallback; keep live model proof opt-in.
