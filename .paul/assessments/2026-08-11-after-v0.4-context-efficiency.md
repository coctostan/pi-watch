## Findings

### Vision alignment

**Strategic question:** Is recent work still serving the project's stated purpose, or has it drifted?

The Core Value remains “cheapest-path-that-works video understanding for the agent — local-first, model-agnostic.” The completed milestones are tightly aligned: v0.1 established the sampler/router/tool foundation, v0.2 proved a swappable local tier-2 model, v0.3 added YouTube captions and pasted-URL operation, and v0.4 added bounded local ASR for captionless speech. There is no thematic drift from the stated product.

The recovered 2026-08-09 `feedback.md` provides concrete field evidence that the implementation does not yet realize “cheapest path” end to end for long, captioned videos. `sample()` currently performs duration probing, scene detection, frame selection, and frame decoding before caption acquisition; only afterward does the router choose tier 1. A transcript-sufficient question can therefore avoid frames in the returned tier-1 result while still paying frame-analysis and decode cost internally. This is already acknowledged as audit-routed R3.

The same feedback reports host-context waste from overlapping rolling captions, head-only transcript truncation, ignored YouTube start timestamps, broad semantic prompts falling through to visual tiers, and tier-3 results carrying both many images and a large transcript. The current code corroborates the mechanisms: `parseWebVtt()` strips markup but preserves every cue payload; tier 1 formats every transcript segment and truncates from the head at Pi's 50 KB / 2,000-line limit; timestamp ranges are not tool parameters; and unrecognized prompts default to visual intent.

Local speech-to-text was the feedback's other major gap, but v0.4 has closed it. The highest-alignment remaining opportunity is therefore not another modality: it is making the existing transcript path genuinely cheap, range-complete, and context-efficient.

### Trajectory

**Strategic question:** Is the project converging toward its goals or sprawling away from them?

Trajectory is strongly convergent: foundation → real local vision → captioned URLs → captionless local speech. Previously settled seams remain intact, and the decision record marks superseded or deferred choices rather than re-litigating them. v0.4 added ASR behind the existing transcript contract and preserved captions-first fallback, demonstrating that the architecture can absorb capability without model-specific forks.

Deferred work is visible but growing. The roadmap carries six audit-routed chains plus CI, tier-3 batch fan-out, effects decomposition, resolver caps, advanced ASR, richer command/config, optional cloud, package publication, and dependency maintenance. The recovered feedback adds several related but differently sized ideas: deterministic caption normalization and range selection; stateful transcript handles; adaptive visual sampling; and model-backed hierarchical synthesis. Treating all of them as one “context optimization” milestone would create sprawl and mix low-risk corrections with new storage and inference architecture.

Recent v0.3→v0.4 growth was substantial but purposeful: 84 repository files changed, with 6,993 insertions and 354 deletions. The largest authored additions were registered-boundary ASR tests and the focused ASR adapter. The main trajectory risk is now over-correcting the feedback by introducing persistence and an internal summarization model before measuring the simpler deterministic gains.

The feedback maps to explicit seams rather than diffuse rewrites:

- Caption overlap normalization belongs in a pure transform around `parseWebVtt()`, with conservative timing-preserving tests.
- URL/range handling belongs at the input/source and transcript-filter boundaries.
- Transcript-before-frame execution requires orchestration decomposition: transcript acquisition and route eligibility must become available before expensive visual effects, while preserving one public `watch` primitive and total tier-3 fallback.

## Strategic Options

- **A. Make transcript-first genuinely cheap and range-complete** — Conservatively deduplicate rolling captions, honor YouTube timestamps and explicit `start`/`end` ranges, acquire enough transcript evidence before frame analysis, short-circuit frame decoding for transcript-sufficient routes, and return coverage/truncation metadata. **Value:** very high; directly addresses observed waste and R3 while reinforcing the Core Value. **Cost:** medium. **Risk:** medium; overlap removal must not erase legitimate repetition, and orchestration must preserve fallback/cleanup guarantees. **Dependencies:** deterministic VTT/range fixtures, a staged sampling boundary, and measurable context/work budgets. No new dependency is inherently required.

- **B. Add durable transcript handles and selective retrieval** — Store full normalized transcripts outside the host conversation and expose continuation, range, and possibly lexical-retrieval operations. **Value:** high for long videos and repeated follow-ups. **Cost:** medium-high. **Risk:** high relative to current architecture because it introduces state, identity, retention, cleanup, privacy, concurrency, and package-install location policy. **Dependencies:** an explicit artifact lifecycle and a stable follow-up tool schema. Best considered after normalization/range semantics are stable.

- **C. Return compact model-synthesized answers by default** — Add hierarchical chunk analysis, question-relevant evidence selection, and compact cited synthesis. **Value:** potentially the largest host-context reduction and best broad-question UX. **Cost:** high. **Risk:** high; tier 1 is currently model-agnostic evidence passthrough, the extension has no guaranteed cheap inference provider, and silently using an optional tier-2 endpoint would change cost/privacy/fallback semantics. **Dependencies:** a separately approved inference boundary, model/config policy, quality evaluation corpus, and clear `answer`/`evidence` output modes.

- **D. Take a hardening/maintenance milestone** — Close R8/R18/R22 and R4/R6, add dedicated CI, address dependency advisories, and perform only test-backed hotspot decomposition. **Value:** medium-high for reliability and contributor confidence. **Cost:** medium. **Risk:** low-medium. **Dependencies:** careful narrowing so unrelated chores do not become a catch-all. This does not address the strongest user-observed context problem by itself.

## Ranked Recommendation

**Recommended next target (non-authoritative): Option A — make the existing transcript path genuinely cheap, normalized, and range-complete before adding stateful artifacts or internal model synthesis.**

**Why this ranks first:** it is the closest match to both the Core Value and concrete user evidence. The architecture already has captions, ASR, timestamps, routing, and bounded outputs; the missing behavior is using those assets in the right order and granularity. Most of the first-order waste can be attacked with pure normalization, explicit range semantics, and orchestration short-circuiting without adding a dependency, persistent cache, or mandatory model. It also closes the most consequential audit-routed R3 discrepancy. Option A creates the normalized transcript and coverage contracts that Options B and C would need later, while producing measurable gains even if those larger options are rejected.

The recommendation intentionally does **not** claim that deterministic changes alone can deliver a compact semantic answer for every broad question. Hierarchical synthesis is a separate inference decision. First measure how much context and work disappear through deduplication, requested-range selection, transcript-first execution, and better coverage metadata; then decide whether the remaining gap justifies stateful handles or model-backed synthesis.

## Actionable Points

- [ ] Treat the recovered feedback as dated field evidence: local ASR is now complete, while caption duplication, timestamp/range loss, head-only truncation, transcript-after-frames execution, and broad semantic routing remain candidate problems to revalidate.
- [ ] Define measurable milestone outcomes before implementation: unique transcript bytes, total tier-1 result bytes, requested range present, coverage metadata accurate, and zero scene/frame decode work for transcript-sufficient cases.
- [ ] Build deterministic rolling-caption fixtures that include true overlap, legitimate repeated speech, markup, multilingual/punctuation edges, and timing preservation; choose a conservative deduplication rule with explicit non-goals.
- [ ] Decide range semantics: YouTube `t`/`start` parsing, optional explicit `start`/`end`, precedence, validation, cue clipping, and behavior when the requested range has no transcript.
- [ ] Design a staged acquisition boundary so captions/eligible ASR can inform routing before scene detection and frame decoding, while keeping source ownership, cleanup, diagnostics, and tier-3 totality intact.
- [ ] Decide whether broad prompts such as “analyze this video” should default to transcript-first, require an explicit semantic/visual mode, or preserve visual routing; do not solve this only by adding more fragile keywords.
- [ ] Add a small versioned context-efficiency evaluation corpus derived from representative long-form cases; separate deterministic pipeline metrics from opt-in answer-quality/live-media checks.
- [ ] Defer transcript handles and default model-backed synthesis unless measured Option-A results leave a material long-video coverage gap; if promoted, plan each as an explicit architecture decision.
- [ ] Decide whether adjacent low-risk audit fixes R8/R18/R22 and terminology reconciliation belong in a final hardening phase or remain separate, rather than allowing them to obscure the milestone's user outcome.
