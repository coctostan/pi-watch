<objective>
## Goal

Implement a best-effort YouTube caption pipeline that fetches human captions when available, falls back to auto-generated captions, parses WebVTT into timestamped `TranscriptSegment`s, and feeds the existing `sample()` timeline so spoken-content questions can route to tier 1 without weakening visual fallback.

## Purpose

Phase 14 made the original YouTube page ref available to transcript lookup while keeping downloaded media and cleanup ownership separate. Phase 15 fills that deferred seam: captions become the cheapest model-agnostic path for spoken questions, while absent or unusable captions continue through the existing tier-2/tier-3 visual chain.

## Output

- A pure, directly tested WebVTT-to-`TranscriptSegment[]` parser in `src/sampler/effects.ts`.
- A bounded, argv-only, subtitle-only `yt-dlp` caption effect with injected process/filesystem dependencies and owned temporary cleanup.
- Public sampler exports for the parser and caption dependency contract in `src/sampler/index.ts`.
- Deterministic offline tests proving caption preference/fallback, parsing, failure degradation, original-ref use, timeline assembly, tier-1 reachability, and visual fallback preservation.
- `.paul/phases/15-caption-transcript-pipeline/15-01-SUMMARY.md` after completion.
</objective>

## AC-1: WebVTT becomes a valid timestamped transcript

```gherkin
Given WebVTT containing ordinary cue identifiers, timestamp ranges, cue settings, multiline text, and caption markup
When the pure caption parser runs
Then it returns ordered non-empty caption segments with integer start/end milliseconds and source "captions"
  And it ignores headers, notes, malformed cues, empty cues, and invalid time ranges without inventing text
```

## AC-2: Human captions are preferred with automatic fallback

```gherkin
Given a supported YouTube watch, short-link, or shorts URL
When transcript fetching runs
Then it uses the canonical original video URL in bounded argv-only yt-dlp subtitle requests with --ignore-config, --no-playlist, and --skip-download
  And it accepts the first valid human-caption VTT result
  And it attempts auto-generated captions only when no valid human-caption transcript was produced
  And it never downloads the media again
```

## AC-3: Caption effects are best-effort and cleanup-owned

```gherkin
Given a local ref, absent captions, malformed or empty VTT, a missing yt-dlp binary, timeout, non-zero exit, unsafe output, read failure, or caption temporary-storage failure
When transcript fetching completes
Then it returns source "none" with no segments rather than throwing or fabricating spoken content
  And every caption temporary directory that was created is removed exactly once
  And caller-owned files and Phase-14 media ownership are untouched
```

```gherkin
  And the existing route includes tier 1 first
  And tier 1 returns transcript content

Given transcript fetching returns source "none"
When the same pipeline evaluates the video
Then the existing tier-2/tier-3 visual route remains available and no spoken content is fabricated
```
