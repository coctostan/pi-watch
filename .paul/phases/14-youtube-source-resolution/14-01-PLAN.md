<objective>
## Goal

Make `sample()` accept supported YouTube URLs by resolving them once through `yt-dlp` into sampler-owned temporary media, while preserving local refs byte-for-byte and guaranteeing cleanup on success and every failure path.

## Purpose

The watch pipeline currently sends pasted YouTube webpage URLs directly to ffprobe/ffmpeg, so URL input is not a reliable sampler source. Phase 14 adds the YouTube-first implementation behind a generic resolver seam without changing the tier contracts, transcript behavior, or local-file path.

## Output

- A typed source-resolution contract and YouTube URL normalization/download effect in `src/sampler/effects.ts`.
- `sample()` orchestration that distinguishes the original ref from the resolved media ref and owns temporary cleanup.
- Public sampler exports for the resolver contract and pure URL helpers.
- Deterministic offline Vitest coverage for URL classification, download/error behavior, ownership, and cleanup.
- `.paul/phases/14-youtube-source-resolution/14-01-SUMMARY.md` after completion.
</objective>

<acceptance_criteria>
## AC-1: Local refs remain borrowed and unchanged

```gherkin
Given a caller supplies a local file reference
When the source resolver and sample pipeline process it
Then the media reference equals the caller reference byte-for-byte
  And ownership is caller-owned with no caller file deletion
  And the resulting WatchedFrameSet source.ref remains the original reference
```

## AC-2: Supported YouTube URLs resolve to owned local media

```gherkin
Given a valid supported YouTube watch, youtu.be, or shorts URL
When the source resolver runs
Then it normalizes the URL deterministically
  And invokes yt-dlp exactly once through an argv array with no shell
  And returns the exact downloaded local media path inside a sampler-created temporary directory
  And marks that media as sampler-owned
```

## AC-3: Temporary ownership is cleaned on all paths

```gherkin
Given a YouTube source resolves to sampler-owned temporary media
When sampling succeeds or any downstream probe, scene-detection, decode, transcript, or assembly step fails
Then the owned temporary directory is removed exactly once through an idempotent cleanup operation
  And no caller-owned path is removed
```

## AC-4: Resolver failures are bounded and legible

```gherkin
Given an unsupported HTTP URL, malformed supported URL, missing yt-dlp executable, download timeout, non-zero download exit, or missing download output
When resolution is attempted
Then sampling rejects with a stage-specific actionable error
  And any temporary directory already created is removed
  And no shell execution or unbounded process is used
```

## AC-5: Existing sampler and tier contracts stay stable

```gherkin
Given existing local-file callers and the current transcript stub
When the full offline suite, typecheck, and build run
Then existing local golden-clip behavior remains green
  And source.ref records the original caller ref rather than the temporary path
  And fetchTranscript still receives the original ref and may degrade to source "none"
  And no watch tier, batch, config, dependency, or contract schema change is required
```
</acceptance_criteria>
