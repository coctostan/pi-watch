<objective>
## Goal

Acquire and range-filter caption or eligible ASR evidence before scene analysis, route broad/spoken/mixed questions against that transcript stage, and return successful tier-1 results with zero scene-detection and frame-decoding work while preserving every visual fallback, cleanup, range, coverage, and output-bound guarantee.

## Purpose

The current `sample()` pipeline pays for full-source scene analysis and frame decode before captions or ASR can make tier 1 available. That contradicts the project's cheapest-path value for transcript-sufficient calls. This plan makes acquisition staged without leaking resolver ownership out of `sample()`: transcript evidence is assembled first, a deterministic question policy decides whether visual evidence is needed, and the existing visual sampler runs only when the selected route requires it. The approved policy is transcript-first for broad and mixed prompts when a non-empty transcript exists; explicitly visual/temporal and on-screen-text prompts remain visual.

## Output

- A deterministic router policy that distinguishes broad and mixed prompts from explicitly visual/temporal and on-screen-text prompts without adding semantic confidence scoring.
- A pure transcript-stage / sampled-frame attachment seam that preserves the public `WatchedFrameSet` and existing `sample()` behavior for callers that do not opt into staged routing.
- Single and batch `watch` orchestration that avoids scene detection and frame decode only when tier 1 deterministically succeeds, while preserving captions-first ASR, cleanup, range, diagnostics, and fallback.
- Deterministic RED/GREEN/REFACTOR evidence, truthful architecture/operator documentation, and exact reproducible `dist/**` output.
</objective>

## Intent Slice

**Served requirements (verbatim):**

- **R3** — **Sampler implementation** — ffmpeg scene-change extraction (one frame per cut) + uniform backfill + budget cap (~16 frames default, configurable) + resolution policy (low-res default, high-res for on-screen-text) + paired transcript merge (captions/Whisper) on the same timeline.
- **R4** — **Router (tier selection)** — decides which tier answers a given question using a defined, deterministic policy: spoken questions with a non-empty transcript use tier 1; absent transcripts and temporal/visual questions use tiers 2/3; on-screen-text questions select the OCR route; every route ends in tier 3. Transcript semantic adequacy/confidence scoring is not part of the current router contract.
- **R5** — **`watch` tool primitive** — takes a **video ref** (a local file path or an explicitly supported YouTube watch/short-link/shorts URL resolved through bounded yt-dlp ownership and cleanup) plus a question, optionally bounded by supported URL timestamps or explicit whole-second `start` / `end` values (single call, or shared across a batch), runs the sampler over that one absolute half-open range, routes to a tier, and returns an answer. *(Amended by Phase 21 plan 21-01; provenance: `.paul/phases/21-range-aware-evidence/21-01-SUMMARY.md`.)*
- **R6** — **Tier adapters** — tier 1 (timestamped transcript delivery), tier 2 (generic OpenAI-compatible sampled-frame vision adapter for local or hosted endpoints), and tier 3 (frames → orchestrator `ImageContent`).
