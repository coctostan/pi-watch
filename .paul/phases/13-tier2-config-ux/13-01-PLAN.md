<objective>
## Goal
Close v0.2 by turning the Phase-12 `unconfigured` tier-2 diagnostic into real **config UX**: a legible, network-free "tier 2 is unconfigured — set X to enable it" guidance message surfaced on the single-video `watch` result, and (pending the Task-1 decision) an **opt-in** sensible local default that auto-points tier 2 at the documented localhost `mlx_vlm` endpoint without making the *default* unconfigured path do any network I/O.

## Purpose
v0.2 ("Tier 2, For Real") made the local native-video tier answer through `/watch` (Phase 10/11) and fail legibly (Phase 12). The remaining gap is the first-run experience: today an unconfigured tier 2 silently escalates to tier 3 and only leaves a machine-readable `details.tier2.reason = "unconfigured"`. A user never sees *how* to turn tier 2 on. This phase delivers the human-facing nudge (and optionally a zero-config local-first default), honoring the project's local-first, model-agnostic, "we own the sampling; backends are thin config" principles.

## Output
- `src/watch/tier2.ts` — a shared, secret-free unconfigured-guidance constant; (option-b) opt-in `WATCH_TIER2_LOCAL` local-default constants + resolution.
- `src/config/config.ts` — (option-b only) doc/precedence note that tier2 may resolve to the opt-in local default.
- `src/watch/extension.ts` — a pure `withUnconfiguredHint` helper that appends the guidance to the single-video `watch` result content when tier 2 was unconfigured and another tier answered.
- `docs/TIER2-SETUP.md` — documents the new guidance message and (option-b) the `WATCH_TIER2_LOCAL` opt-in.
- Tests: extended `config.test.ts` / `tier2.test.ts` plus a new `test/watch/extension-unconfigured-hint.test.ts`.
- `.paul/phases/13-tier2-config-ux/13-01-SUMMARY.md` after completion.
</objective>

## AC-1: Unconfigured guidance is surfaced on the single-video `watch` result
```gherkin
Given tier 2 is unconfigured (WATCH_TIER2_BASE_URL and/or WATCH_TIER2_MODEL unset and no opt-in local default)
  And the watch routes to tier 2 then escalates so another tier (1 or 3) answers
When the `watch` tool returns its result
Then the result content includes a concise, secret-free guidance line naming WATCH_TIER2_BASE_URL and WATCH_TIER2_MODEL and pointing to docs/TIER2-SETUP.md
  And the original answer content is preserved ahead of the guidance line
```

## AC-2: No guidance noise when tier 2 is configured, answers, or fails for a non-unconfigured reason
```gherkin
Given a watch where tier 2 either answers (final tier === 2) OR fails for reason http-error / empty-answer / timeout / network-error
When the `watch` tool returns its result
Then NO unconfigured guidance line is appended to the content
```

## AC-3: The default unconfigured path stays network-free
```gherkin
Given no WATCH_TIER2_* configuration and no opt-in local-default flag set
When tier 2 is reached
Then resolveTier2ConfigFromEnv returns null and the runner emits reason "unconfigured" with zero network calls (unchanged Phase-12 contract)
```

## AC-4: Opt-in local default (Task-1 option-b only) is network-free by default and secret-free
```gherkin
Given WATCH_TIER2_BASE_URL and WATCH_TIER2_MODEL are unset
When WATCH_TIER2_LOCAL is "1"
Then resolveTier2ConfigFromEnv returns the documented localhost endpoint { baseURL: "http://localhost:8080/v1", model: "mlx-community/Qwen3-VL-8B-Instruct-4bit" }
  And when WATCH_TIER2_LOCAL is unset/any other value it still returns null (default path unchanged, no localhost call)
  And explicit WATCH_TIER2_BASE_URL/WATCH_TIER2_MODEL always take precedence over the local default
  And no message, constant, or diagnostic ever contains an api key or Authorization header
```
